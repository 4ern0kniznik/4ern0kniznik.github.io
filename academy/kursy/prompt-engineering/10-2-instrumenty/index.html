Зачем это

Модель плохо считает большие числа и не знает, что лежит в вашей базе. Инструменты закрывают эти дыры: калькулятор, поиск по базе, поиск в интернете. Поймёте, как это устроено, — будете понимать, когда ассистент посчитал сам, а когда взял число из инструмента.

Урок

Что такое вызов инструмента

Вызов инструмента (tool use, ещё говорят function calling) звучит сложно, но собран из того, что вы уже знаете: подстановки и цепочки подсказок.

Модель сама ничего не запускает. Она только пишет текст. Поэтому вызов идёт в три шага:

  1. Модель пишет, какой инструмент нужен и с какими данными. Например: «калькулятор, 1 984 135 × 9 343 116».
  2. Модель останавливается. Программа вокруг неё запускает инструмент.
  3. Результат подставляют обратно в разговор, и модель продолжает ответ уже с ним.

Шаг 3 — та же цепочка из урока 10.1. Только вход второго шага дал не человек и не модель, а инструмент.

Что можно дать модели как инструмент:

  • калькулятор;
  • счётчик слов или знаков;
  • запрос к базе данных: найти клиента, остаток на складе, статус заказа;
  • справочный сервис: курс валют, погода, расписание.

Из чего собирается

Нужны две вещи.

  1. Описание инструментов. Обычно в системной подсказке: что за инструмент, как его вызвать, какие у него поля и что в каждом поле.
  2. Обвязка. Программа, которая замечает вызов, запускает инструмент и возвращает результат модели.

Хорошее описание — половина успеха. Модель выбирает инструмент по описанию. Если там написано «калькулятор: сложение, вычитание, умножение», делить через него она может и не стать.

Когда инструмент не нужен

Модель с калькулятором не должна звать его на каждый вопрос. На «Какая столица Татарстана?» она ответит сама. В оригинале это проверяют отдельным примером, и модель справляется: вызов появляется, только когда задача его требует.

Как попробовать в чате: вы — инструмент

Обвязку можно сыграть руками. Вы будете калькулятором. Системная подсказка (или первое сообщение):

текст
У тебя есть инструмент «калькулятор». Сам большие числа не перемножай и не складывай.
Когда нужно посчитать, напиши одну строку и остановись:
ВЫЗОВ: калькулятор(<число>, <операция + - * />, <число>)
Я пришлю ответ строкой:
РЕЗУЛЬТАТ: <число>
После этого продолжай. Если считать не нужно, отвечай сразу, без вызова.

Вопрос:

текст
Умножь 1 984 135 на 9 343 116.

Ассистент должен ответить строкой ВЫЗОВ: …. Посчитайте на обычном калькуляторе и пришлите:

текст
РЕЗУЛЬТАТ: 18538003464660

Ассистент должен написать итог с этим числом. Затем спросите что-нибудь без счёта, например про столицу Татарстана. Вызова быть не должно.

Где инструменты уже встроены

В чат-ассистентах вы пользуетесь инструментами, даже если об этом не думаете.

  • Поиск в интернете. Если в ответе есть ссылки на свежие страницы, ассистент, скорее всего, искал. Без поиска модель знает только то, что было в её обучающих данных.
  • Работа с файлами. Когда вы прикладываете таблицу и просите посчитать итоги, часть ассистентов запускает для этого код, а не считает «в уме». Это тоже инструмент.
  • Корпоративные системы. Компании подключают к ассистенту свои базы: CRM, склад, справочники. Принцип тот же: описание инструмента и обвязка.

Какие инструменты включены в «Немо» на пилоте, зависит от настроек шлюза. Нет данных — уточните у преподавателя. Если не уверены, был ли вызов, спросите прямо: «Ты искал это в интернете или ответил по памяти?» И проверьте ссылки сами.

Упражнения

Упражнение 10.2.1. Мини-база

В оригинале упражнение про «самую маленькую базу данных» с пользователями и товарами. У нас — клиенты и товары небольшого склада. Вымышленные.

База:

текст
Клиенты:
1 — ООО «Альфа-Снаб», zakaz@alfa-snab.example
2 — АО «Берёзка-Логистик», office@berezka-log.example
3 — ООО «Вектор», info@vektor.example

Товары:
1 — Паллета деревянная, 450 ₽
2 — Стретч-плёнка 500 мм, 1 290 ₽
3 — Короб гофрированный 60×40×40, 85 ₽

Напишите системную подсказку с описанием четырёх инструментов: найти_клиента, найти_товар, добавить_клиента, добавить_товар. Для каждого — что делает, какие поля, какого типа (число, текст) и что в каждом поле. Формат вызова — как в примере с калькулятором. Базу в подсказку не вставляйте: модель видит её только через инструменты, а роль инструмента играете вы.

Отправьте по очереди, каждое в новом чате:

текст
Добавь в базу клиента ООО «Дельта-Трейд».
текст
Добавь в базу товар «Скотч упаковочный».
текст
Как называется клиент № 2?
текст
Как называется товар № 3?

Проверка:

  • первый запрос → вызов добавить_клиента с названием «ООО «Дельта-Трейд»». Почты в запросе нет: ассистент её спрашивает или оставляет поле пустым, но не выдумывает;
  • второй → добавить_товар с названием; цены в запросе нет, и ассистент её не выдумывает;
  • третий → найти_клиента с номером 2; после вашего РЕЗУЛЬТАТ ответ: АО «Берёзка-Логистик»;
  • четвёртый → найти_товар с номером 3; ответ: короб гофрированный.
Подсказка

Опишите каждое поле одной строкой: имя, тип, смысл. Например: «номер — число, номер клиента в базе». Добавьте правило: «Если для вызова не хватает данных, спроси у пользователя, не придумывай». В оригинале запрос на добавление товара тоже без цены. Посмотрите, что сделает модель без этого правила.

Практика Академии

Задача. Вы бухгалтер. Ассистент помогает с расчётом аренды, но считать сам не должен: все суммы — только через калькулятор, то есть через вас.

Возьмите системную подсказку с калькулятором из урока и отправьте:

текст
Аренда склада — 1 984 135 ₽ в месяц, договор на 37 месяцев. Сколько всего заплатим по договору? Потом скажи, сколько это в среднем за год.

Отвечайте на каждый вызов результатом с обычного калькулятора.

Проверка (эталон):

  • первый вызов: калькулятор(1984135, *, 37); вы отвечаете РЕЗУЛЬТАТ: 73412995;
  • второй вызов на среднее за год: делим общую сумму на 37 и умножаем на 12, или 1 984 135 × 12; в обоих случаях ответ 23 809 620 ₽;
  • в итоговом ответе обе суммы совпадают с вашими результатами до рубля;
  • ни одного числа, посчитанного без вызова (кроме исходных 1 984 135, 37 и 12).

Если ассистент посчитал что-то сам, допишите в подсказку: «Любое арифметическое действие — только через вызов» и повторите в новом чате.

Сравните модели

Отправьте подсказку с калькулятором и задачу из «Практики» в два-три ассистента. Посмотрите:

  • держит ли модель формат ВЫЗОВ: … или сразу пишет ответ;
  • останавливается ли после вызова или «досчитывает» за вас;
  • не зовёт ли калькулятор там, где он не нужен (вопрос про столицу);
  • что делает, когда данных для вызова не хватает: спрашивает или придумывает.

Готовых ответов моделей здесь нет: прогона не было. Запишите, какая модель нарушила правило и как.

Для разработчиков

В оригинале (2024 год, модель Claude 3 Sonnet) инструменты описаны прямо в системной подсказке, в XML-разметке. Вызов модели ловят по стоп-последовательности — закрывающему тегу вызова. Программа вытаскивает параметры из текста, запускает функцию на Python и возвращает результат в разметке «результаты функции». Сам курс предупреждает, что формат будет меняться.

Сейчас у API Anthropic есть отдельный параметр tools. Инструмент описывается тремя полями: name (имя), description (что делает и когда звать), input_schema (поля входа в формате JSON Schema). Схематично, для нашего калькулятора:

json
{
  "name": "calculator",
  "description": "Арифметика над двумя числами: + - * /",
  "input_schema": {
    "type": "object",
    "properties": {
      "a": {"type": "number"},
      "op": {"type": "string", "enum": ["+", "-", "*", "/"]},
      "b": {"type": "number"}
    },
    "required": ["a", "op", "b"]
  }
}

Модель возвращает блок tool_use с именем инструмента и полями. Ваш код выполняет вызов и отправляет результат блоком tool_result с тем же идентификатором вызова. Подробно: platform.claude.com/docs/en/agents-and-tools/tool-use/overview.

У OpenAI-совместимых API устройство похожее: тот же параметр tools, описание функции по JSON Schema, ответ с вызовом функции. Названия полей отличаются — смотрите документацию своего API.
