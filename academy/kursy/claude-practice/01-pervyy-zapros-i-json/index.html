Зачем это

Ответ модели в чате читает человек. Ответ модели в программе читает код. Коду нужен JSON без вступлений вроде «Вот ваш JSON:». В этом уроке вы отправите первый запрос из Python и научитесь надёжно доставать JSON из ответа.

Урок

Подготовка

bash
pip install anthropic
export ANTHROPIC_API_KEY="ваш ключ"   # Windows: set ANTHROPIC_API_KEY=ваш ключ

Если ключ выдан через шлюз (например, «Немо»), в инструкции к нему будет адрес API. Тогда клиент создаётся с параметром base_url. Формат шлюза «Немо» и сроки выдачи ключей — нет данных.

python
import json, re
from anthropic import Anthropic

MODEL = "впишите-имя-модели"  # актуальное имя — в документации вендора
client = Anthropic()  # ключ из ANTHROPIC_API_KEY; для шлюза: Anthropic(base_url="адрес из инструкции")

Первый запрос

Запрос состоит из трёх обязательных частей: модель, предел длины ответа max_tokens и список сообщений. Системная подсказка из урока 1 курса К1 передаётся отдельным параметром system.

python
resp = client.messages.create(
    model=MODEL,
    max_tokens=1024,
    system="Ты помощник бухгалтера. Отвечай коротко.",
    messages=[{"role": "user", "content": "Что такое УПД? Одно предложение."}],
)

def text_of(resp):
    # ответ — список блоков; текст лежит в блоках типа "text"
    return "".join(b.text for b in resp.content if b.type == "text")

print(text_of(resp))
print(resp.stop_reason)  # end_turn — закончил сам, max_tokens — упёрся в предел

Ответ приходит списком блоков. Сейчас там один текстовый блок, но в следующих уроках появятся блоки вызова инструментов и рассуждений. Поэтому текст собираем по типу блока, а не берём content[0] вслепую.

Просим JSON

Попросите JSON прямо и опишите поля. Без описания модель придумает свои ключи, и они будут меняться от запроса к запросу.

python
invoice = """Счёт на оплату № 214 от 28.10.2026
Поставщик: ООО «Северный картон»
Бумага офисная А4, 40 пачек × 520,00 ₽ = 20 800,00 ₽
Итого: 20 800,00 ₽, в т. ч. НДС 3 750,82 ₽"""

prompt = f"""Извлеки из счёта данные в JSON с ключами:
number — номер счёта, строка;
date — дата в формате ДД.ММ.ГГГГ;
supplier — поставщик, как в счёте;
total — итог в рублях, число с точкой;
vat — НДС в рублях, число с точкой, или null, если НДС нет.

<invoice>
{invoice}
</invoice>"""

resp = client.messages.create(model=MODEL, max_tokens=1024,
                              messages=[{"role": "user", "content": prompt}])
print(text_of(resp))

Модель может ответить JSON-ом в обёртке: строка вступления, блок ``json, пояснение после. Первый способ достать JSON — взять всё от первой { до последней }`:

python
def extract_json(text):
    start, end = text.index("{"), text.rindex("}")
    return json.loads(text[start:end + 1])

Способ простой и ломается, если объектов в ответе несколько или в пояснении после JSON есть фигурная скобка.

Теги и стоп-последовательность

Надёжнее попросить положить JSON в теги и остановить ответ на закрывающем теге. Стоп-последовательность (stop sequence) обрывает генерацию, как только модель её напишет. Сам стоп-текст в ответ не попадает.

python
prompt_tags = prompt + "\n\nВыведи только JSON внутри тегов <json></json>."

resp = client.messages.create(
    model=MODEL, max_tokens=1024,
    stop_sequences=["</json>"],
    messages=[{"role": "user", "content": prompt_tags}],
)
text = text_of(resp)
data = json.loads(text.split("<json>", 1)[1])   # всё после открывающего тега
print(data, resp.stop_reason)                    # stop_reason == "stop_sequence"

Если объектов несколько, каждый кладут в свой тег и забирают регулярным выражением:

python
def between_tags(tag, text):
    return [m.strip() for m in re.findall(f"<{tag}>(.+?)</{tag}>", text, re.DOTALL)]

Модель успевает написать текст до тега, например рассуждение. Это плюс: можно разрешить ей подумать, а в код забрать только содержимое тегов.

Что в оригинале устарело

В оригинале есть ещё один приём: дописать начало ответа за модель (prefill), например открывающую {. В заметке к ноутбуку на 04.11.2026 сказано: этот приём принимает только старая модель Claude Haiku 4.5, а текущие модели отвечают ошибкой 400 на запрос, который заканчивается репликой ассистента. Поэтому в уроке его нет.

Там же сказано, что у текущих моделей есть режим структурированного вывода (structured outputs): ответ гарантированно совпадает с JSON-схемой. Описание — platform.claude.com/docs/en/build-with-claude/structured-outputs. Схемы и строгая проверка разобраны в уроке 3. Теги и стоп-последовательность работают на всех моделях, в том числе у других вендоров, поэтому начинаем с них.

Практика Академии

Задача. Бухгалтерия получает счета текстом из писем. Нужно собрать реестр: номер, дата, поставщик, итог, НДС. Напишите функцию parse_invoice(text) -> dict на приёмах урока, прогоните через неё три счёта и сохраните результат в ответ_01.json.

python
INVOICES = [
"""Счёт № 0457 от 01.11.2026. ООО «Ладога-Опт». Вода питьевая 19 л, 12 шт. по 350 руб. Всего к оплате 4 200 руб. 00 коп., в том числе НДС 757,38 руб.""",
"""ИП Смирнова А. В. (вымышленный поставщик)
Счёт 33/11 от 03.11.2026
Ремонт кондиционера в переговорной — 7 500,00
Без НДС (УСН). Итого: 7 500,00 ₽""",
"""Счёт на оплату № СК-1182 от 30.10.2026
Поставщик: АО «Техносклад»
1. Картридж лазерный — 3 шт. × 4 990,00 = 14 970,00
2. Доставка — 1 × 600,00 = 600,00
Итого: 15 570,00. В том числе НДС: 2 807,70""",
]

results = [parse_invoice(t) for t in INVOICES]
json.dump(results, open("ответ_01.json", "w", encoding="utf-8"), ensure_ascii=False, indent=2)

Проверка. Запустите скрипт; он не обращается к модели и сверяет ваш файл с эталоном.

python
import json, re

ETALON = [
    {"number": "0457",    "date": "01.11.2026", "total": 4200.00,  "vat": 757.38},
    {"number": "33/11",   "date": "03.11.2026", "total": 7500.00,  "vat": None},
    {"number": "СК-1182", "date": "30.10.2026", "total": 15570.00, "vat": 2807.70},
]
SUPPLIER_WORDS = ["ладога", "смирнова", "техносклад"]

got = json.load(open("ответ_01.json", encoding="utf-8"))
assert len(got) == 3, "должно быть три счёта"
for i, (g, e) in enumerate(zip(got, ETALON), 1):
    assert set(g) >= {"number", "date", "supplier", "total", "vat"}, f"счёт {i}: не хватает ключей"
    assert re.fullmatch(r"\d{2}\.\d{2}\.\d{4}", g["date"]), f"счёт {i}: дата не ДД.ММ.ГГГГ"
    assert g["number"] == e["number"] and g["date"] == e["date"], f"счёт {i}: номер или дата"
    assert isinstance(g["total"], (int, float)) and abs(g["total"] - e["total"]) < 0.005, f"счёт {i}: итог"
    if e["vat"] is None:
        assert g["vat"] is None, f"счёт {i}: НДС должен быть null"
    else:
        assert abs(g["vat"] - e["vat"]) < 0.005, f"счёт {i}: НДС"
    assert SUPPLIER_WORDS[i - 1] in g["supplier"].lower(), f"счёт {i}: поставщик"
print("Все три счёта разобраны верно")

Засчитано, если скрипт печатает «Все три счёта разобраны верно». Типичные ошибки: номер «№ 0457» вместо «0457», ноль вместо null при «Без НДС», итог строкой с пробелами. Каждую чините правилом в подсказке, а не правкой эталона.

Сравните модели

Тот же приём на другой модели через OpenAI-совместимый API (DeepSeek, YandexGPT, GigaChat и другие, если у вас есть их ключ):

python
import os
from openai import OpenAI

alt = OpenAI(api_key=os.environ["ALT_API_KEY"], base_url=os.environ["ALT_BASE_URL"])  # адрес — в документации вендора
ALT_MODEL = "впишите-имя-модели"  # актуальное имя — в документации вендора

r = alt.chat.completions.create(
    model=ALT_MODEL, max_tokens=1024,
    stop=["</json>"],  # стоп-последовательность; поддержку проверьте в документации вендора
    messages=[{"role": "user", "content": prompt_tags}],
)
text = r.choices[0].message.content

Отличия формата: системная подсказка идёт первым сообщением с ролью system, текст лежит в choices[0].message.content, стоп-последовательность называется stop.
