Первый запрос: Responses API, инструкции, продолжение разговора

Зачем это

Модель в чате отвечает человеку. Модель в программе отвечает скрипту: он разбирает почту, сортирует заявки, пишет черновики. Этот урок — первый такой скрипт: отправить запрос, прочитать ответ, продолжить разговор и узнать, сколько токенов ушло.

Урок

Что такое Responses API

У OpenAI два основных способа отправить запрос модели:

  • Chat Completions — старый и самый распространённый. Вы сами храните историю разговора и каждый раз отправляете её целиком.
  • Responses API — новый, с 2025 года. Умеет хранить разговор на стороне OpenAI, подключать встроенные инструменты (поиск в интернете, поиск по файлам) и принимать на вход текст и картинки в одном запросе.

В курсе работаем с Responses API. Где приём переносится на Chat Completions, говорим об этом отдельно: формат Chat Completions понимают и другие провайдеры с OpenAI-совместимым API.

Подготовка

bash
pip install openai
export OPENAI_API_KEY="ваш_ключ"   # Windows: set OPENAI_API_KEY=ваш_ключ

Ключ — в переменной окружения. Библиотека сама его найдёт. В текст скрипта ключ не пишите: скрипт попадёт в git, письмо или чат, и ключ уйдёт вместе с ним.

Первый запрос

python
from openai import OpenAI

MODEL = "..."  # актуальное имя модели — в документации OpenAI

client = OpenAI()  # ключ берётся из OPENAI_API_KEY

response = client.responses.create(
    model=MODEL,
    input="Объясни одним предложением, что такое счёт-фактура.",
)
print(response.output_text)

output_text — готовый текст ответа. Внутри response.output лежит список элементов: сообщение модели, а иногда ещё рассуждение или вызов инструмента. Для простого запроса хватает output_text. Элементы output разберём в уроке 3.

В оригинале ответ достают так: response.output[0].content[0].text. Это работает, пока первый элемент — сообщение. У моделей с рассуждением (reasoning) первым идёт элемент рассуждения, и такой код падает. output_text собирает текст из всех сообщений и надёжнее.

Инструкции — системная подсказка в API

Параметр instructions — то, что в чате называется системной подсказкой: кто модель и как отвечает. Пишется отдельно от вопроса.

python
INSTRUCTIONS = (
    "Ты помощник бухгалтерии ООО «Северный ветер». "
    "Отвечай коротко, по-русски, суммы — в рублях с пробелом между разрядами: 12 500 ₽. "
    "Если данных не хватает, так и скажи и не придумывай."
)

response = client.responses.create(
    model=MODEL,
    instructions=INSTRUCTIONS,
    input="Поставщик прислал счёт на 48 300 ₽ без НДС. Сколько будет с НДС 22 %?",
)
print(response.output_text)

Как писать сами инструкции, подробно разобрано в курсе К1. Здесь важно одно: инструкции отделены от данных. Письмо клиента, текст договора, строка выгрузки идут в input, правила — в instructions.

Продолжение разговора

Responses API по умолчанию хранит ответ на стороне OpenAI. У каждого ответа есть id. Передайте его в previous_response_id, и модель увидит весь предыдущий разговор — пересылать историю не нужно.

python
first = client.responses.create(
    model=MODEL,
    instructions=INSTRUCTIONS,
    input="Напиши тему письма поставщику: просим перевыставить счёт № 214 от 28.10.2026.",
)
print(first.output_text)

second = client.responses.create(
    model=MODEL,
    instructions=INSTRUCTIONS,  # инструкции передаём заново: они не наследуются
    input="Теперь само письмо, 4–5 строк.",
    previous_response_id=first.id,
)
print(second.output_text)

Ответвление. От одного ответа можно продолжить разговор двумя разными путями: два запроса с одним и тем же previous_response_id. Так удобно сравнивать варианты: от одной темы письма — строгое письмо и мягкое.

Про хранение. Раз ответы хранятся у OpenAI, всё, что вы отправили, тоже там. Это ещё одна причина не отправлять персональные данные и настоящие договоры. Как отключить хранение и сколько оно длится, смотрите в документации (параметр store).

Если провайдер не поддерживает previous_response_id, историю ведут сами: список сообщений, к которому каждый раз добавляется новое. Так работает Chat Completions.

Сколько это стоило

В каждом ответе есть usage — сколько токенов ушло на вход и на выход.

python
print(response.usage)
# смотрите поля input_tokens, output_tokens, total_tokens

Модели с рассуждением тратят ещё и скрытые токены рассуждения. Их не видно в ответе, но они считаются в выходных и занимают окно контекста. В оригинале это показано на модели o4-mini (2025 год). Цены за токен — на странице цен OpenAI. Учёт расходов подробно — в уроке 15.

Что ещё есть в оригинале

В ноутбуке OpenAI показаны встроенный поиск в интернете (tools=[{"type": "web_search"}]) и запрос с картинкой. Поиск в интернете вернёт ответ со ссылками на источники. Картинки и документы разберём в уроке 6, инструменты — в уроках 3 и 10.

Упражнения

Упражнение 1.1. Первый ответ

Отправьте запрос: «Сформулируй в одном предложении, чем акт сверки отличается от счёта». Выведите output_text и usage.

Проверка: скрипт печатает одно-два предложения на русском и три числа токенов: вход, выход, всего.

Подсказка

Если скрипт падает с ошибкой авторизации, проверьте, что переменная OPENAI_API_KEY задана в том же окне терминала, где вы запускаете скрипт.

Упражнение 1.2. Инструкции

Задайте instructions: «Отвечай только числом, без слов и без знака рубля». Вопрос: «Счёт на 15 000 ₽ без НДС. Сколько с НДС 22 %?»

Проверка: в output_text только 18300 или 18 300. Никаких слов.

Подсказка

Если модель всё равно пишет «Ответ: …», добавьте в инструкции пример правильного ответа: «Пример: 12000».

Упражнение 1.3. Продолжение и ответвление

  1. Попросите тему письма: «просим продлить договор поставки № 47-П до 31.12.2027».
  2. От этого ответа сделайте два продолжения с одним previous_response_id: «письмо строгим тоном» и «письмо дружелюбным тоном».

Проверка: оба письма упоминают договор № 47-П и дату 31.12.2027, хотя во втором и третьем запросе вы их не писали. Тон писем различается.

Подсказка

Если номер договора пропал, проверьте, что передаёте first.id, а не id строгого письма.

Практика Академии

Задача. В общий ящик ООО «Северный ветер» приходят заявки. Скрипт должен отнести каждую к одному отделу: бухгалтерия, склад, ИТ, договорной.

Заявки и правильные ответы (эталон):

№ЗаявкаЭталон
1Пришлите, пожалуйста, акт сверки за III квартал 2026 года.бухгалтерия
2Не печатает принтер на втором этаже, горит красная лампа.ИТ
3Когда отгрузите 40 коробок бумаги А4 по заказу от 02.11.2026?склад
4Прошу согласовать допсоглашение № 3 к договору аренды.договорной
5В счёте № 512 неверный ИНН покупателя, перевыставьте.бухгалтерия
6Не открывается 1С, пишет «нет лицензии».ИТ
7На складе недостача 3 паллет, нужна инвентаризация.склад
8Контрагент прислал протокол разногласий к договору поставки.договорной
9Оплата по счёту № 77 прошла дважды, верните переплату 12 400 ₽.бухгалтерия
10Нужен доступ к общей папке отдела закупок для нового сотрудника.ИТ

Что сделать:

  1. Напишите instructions: список отделов и правило «ответь одним словом из списка».
  2. Для каждой заявки — отдельный запрос (без previous_response_id: заявки не связаны).
  3. Сравните ответ с эталоном и посчитайте совпадения.

Заготовка проверки:

python
TICKETS = [("Пришлите, пожалуйста, акт сверки…", "бухгалтерия"), ...]  # все 10 из таблицы

correct = 0
for text, expected in TICKETS:
    r = client.responses.create(model=MODEL, instructions=INSTRUCTIONS, input=text)
    answer = r.output_text.strip().lower().rstrip(".")
    ok = answer == expected.lower()
    correct += ok
    print("OK " if ok else "ОШИБКА", text[:40], "→", answer)
print(f"Совпало: {correct} из {len(TICKETS)}")

Проверка:

  • скрипт печатает «Совпало: N из 10», N не меньше 9;
  • каждый ответ — ровно одно слово из списка: ни «Отдел: ИТ», ни точки в конце. Если модель добавляет лишнее, правьте instructions, а не код проверки;
  • суммарный расход токенов по всем 10 запросам выведен одной строкой (сложите usage.total_tokens).

Сравните модели

  1. Запустите практику с двумя-тремя значениями MODEL из списка доступных вам моделей.
  2. Если у вас есть ключ провайдера с OpenAI-совместимым Chat Completions, перепишите вызов так: client = OpenAI(base_url=..., api_key=...), client.chat.completions.create(model=..., messages=[{"role": "system", "content": INSTRUCTIONS}, {"role": "user", "content": text}]), ответ — choices[0].message.content. Адрес и имя модели — в документации провайдера.

Запишите в таблицу: модель, сколько совпало из 10, на какой заявке ошиблась, сколько токенов ушло. Готовых результатов прогона у нас нет: таблицу заполняете вы.

На что смотреть: заявки 4 и 8 (договорной) модели путают с бухгалтерией, заявку 10 — с кадрами, которых в списке нет. Это ожидание, а не измерение: проверьте на своих моделях.
