Зачем это

Модель пишет текст и иногда ошибается в арифметике. В бухгалтерии ошибка в копейку — это неверный счёт-фактура. Решение — дать модели инструмент: вашу функцию, которая считает точно. Модель решает, когда её вызвать и с какими числами, а считает ваш код.

Урок

Как устроен вызов инструмента

В К1 (урок 10.2) вы играли роль инструмента руками. Теперь это делает программа. Шаги:

  1. Вы передаёте в запрос описание инструментов: имя, назначение, поля на входе.
  2. Модель отвечает блоком tool_use: имя инструмента и входные данные. stop_reason в этом случае равен tool_use.
  3. Ваш код запускает функцию.
  4. Вы отправляете результат обратно блоком tool_result с тем же id, и модель дописывает ответ.

Модель сама ничего не запускает. Она только просит. Что выполнить, решает ваш код.

Функция

В оригинале калькулятор считает выражение через eval, и авторы честно предупреждают, что так делать нельзя. eval выполнит любой код, который придёт от модели. Мы напишем узкую функцию: она умеет одно — НДС.

python
from decimal import Decimal, ROUND_HALF_UP

KOP = Decimal("0.01")

def vat(amount: str, rate: float, mode: str) -> dict:
    """mode="included": НДС уже в сумме, выделяем; mode="on_top": начисляем сверху."""
    a, r = Decimal(amount), Decimal(str(rate))
    if mode == "included":
        tax = (a * r / (100 + r)).quantize(KOP, ROUND_HALF_UP)
        net, gross = a - tax, a
    elif mode == "on_top":
        tax = (a * r / 100).quantize(KOP, ROUND_HALF_UP)
        net, gross = a, a + tax
    else:
        raise ValueError(f"неизвестный режим {mode}")
    return {"net": str(net), "vat": str(tax), "gross": str(gross)}

Деньги считаем в Decimal. Во float 0.1 + 0.2 даёт 0.30000000000000004. Ставку функция не знает. Её передаёт модель из условия задачи, а действующую ставку на дату документа проверяет человек.

Описание инструмента

Модель выбирает инструмент по описанию. Пишите его как инструкцию новому сотруднику: что делает, когда звать, что в каждом поле.

python
TOOLS = [{
    "name": "vat",
    "description": ("Точный расчёт НДС до копейки. Вызывай для любой суммы с НДС, "
                    "сам НДС не считай. mode=included — НДС уже в сумме, его надо выделить; "
                    "mode=on_top — НДС начисляется сверху."),
    "input_schema": {
        "type": "object",
        "properties": {
            "amount": {"type": "string", "description": "Сумма в рублях, точка-разделитель, без пробелов: 118000.00"},
            "rate":   {"type": "number", "description": "Ставка НДС в процентах из условия задачи"},
            "mode":   {"type": "string", "enum": ["included", "on_top"]},
        },
        "required": ["amount", "rate", "mode"],
    },
}]

Имя инструмента — латиница, цифры, _ и -. Кириллицу в имени API не примет, а в описании пишите по-русски.

Цикл запроса

Оригинал обрабатывает один вызов и делает второй запрос. На практике модели нужно два-три вызова: например, выделить НДС из двух сумм. Поэтому сразу пишем цикл.

python
import json
from anthropic import Anthropic

MODEL = "впишите-имя-модели"  # актуальное имя — в документации вендора
client = Anthropic()

def ask(question, log=None):
    messages = [{"role": "user", "content": question}]
    for _ in range(5):  # предел шагов: модель не должна крутиться вечно
        resp = client.messages.create(model=MODEL, max_tokens=1024,
                                      tools=TOOLS, messages=messages)
        if resp.stop_reason != "tool_use":
            return "".join(b.text for b in resp.content if b.type == "text")
        messages.append({"role": "assistant", "content": resp.content})
        results = []
        for b in resp.content:
            if b.type != "tool_use":
                continue
            out = vat(**b.input)
            if log is not None:
                log.append({"input": b.input, "output": out})
            results.append({"type": "tool_result", "tool_use_id": b.id,
                            "content": json.dumps(out, ensure_ascii=False)})
        messages.append({"role": "user", "content": results})
    raise RuntimeError("модель не закончила за 5 шагов")

Три детали, на которых чаще всего ошибаются:

  • Ответ модели с вызовом (resp.content) кладут в историю целиком, как реплику ассистента.
  • Все результаты одного шага идут одним сообщением пользователя, по блоку на каждый вызов.
  • tool_use_id в результате совпадает с id вызова. Иначе API вернёт ошибку.
python
log = []
print(ask("Счёт на 118 000,00 ₽ с НДС 20 %. Сколько НДС и сколько без НДС?", log))
print(log)

Когда инструмент не нужен

Модель с инструментом не обязана звать его на каждый вопрос. Спросите «Что такое счёт-фактура?» — вызова не будет, log останется пустым. В оригинале это видно на примерах, где вызов появляется только при расчёте.

Упражнения

Упражнение 2.1. Сверху или внутри

Спросите: «Услуга стоит 50 000 ₽ без НДС, ставка 20 %. Сколько выставить клиенту?»

Проверка: в log один вызов с mode="on_top", в ответе сумма 60 000,00 ₽.

Подсказка

Если модель выбрала included, допишите в описание поля mode пример: «"без НДС" в условии значит on_top».

Упражнение 2.2. Два вызова

Спросите про две суммы сразу: «Выдели НДС 20 % из 24 000 ₽ и из 1 999,99 ₽».

Проверка: в log два вызова; для 1 999,99 НДС равен 333,33 ₽.

Подсказка

Модель может сделать оба вызова в одном шаге. Цикл выше это поддерживает: он обходит все блоки tool_use.

Практика Академии

Задача. Сначала докажите, что функция считает верно. Потом — что модель её зовёт и переносит число в ответ без искажений.

Часть 1. Тесты функции (без модели и без сети):

python
def test_vat():
    assert vat("118000.00", 20, "included") == {"net": "98333.33", "vat": "19666.67", "gross": "118000.00"}
    assert vat("100000", 20, "on_top")       == {"net": "100000", "vat": "20000.00", "gross": "120000.00"}
    assert vat("1000.00", 22, "included")    == {"net": "819.67", "vat": "180.33", "gross": "1000.00"}
    assert vat("0.05", 20, "included")["vat"] == "0.01"
    try:
        vat("100", 20, "сверху")
        raise AssertionError("неизвестный режим должен давать ошибку")
    except ValueError:
        pass
    print("Функция vat считает верно")

test_vat()

Часть 2. Модель и инструмент. Прогоните пять вопросов и проверьте журнал:

python
CASES = [
    ("Счёт на 236 000,00 ₽, НДС 20 % включён. Сколько НДС?",            "included", "236000", "39333.33"),
    ("Начисли НДС 20 % на 12 345,67 ₽.",                                 "on_top",   "12345.67", "2469.13"),
    ("Сумма договора 1 220 000 ₽ с НДС 22 %. Выдели НДС.",               "included", "1220000", "220000.00"),
    ("Сколько будет с НДС 10 %, если без НДС 8 400 ₽?",                  "on_top",   "8400", "840.00"),
    ("Что такое УПД? Ответь одним предложением.",                         None, None, None),
]

for q, mode, amount, expected_vat in CASES:
    log = []
    answer = ask(q, log)
    if mode is None:
        assert log == [], f"лишний вызов на вопрос: {q}"
        continue
    assert len(log) >= 1, f"нет вызова: {q}"
    call = log[0]
    assert call["input"]["mode"] == mode, f"режим: {q}"
    assert Decimal(call["input"]["amount"]) == Decimal(amount), f"сумма: {q}"
    assert call["output"]["vat"] == expected_vat, f"НДС: {q}"
    digits = answer.replace(" ", "").replace(" ", "").replace(",", ".")
    assert expected_vat in digits, f"в ответе нет числа {expected_vat}: {q}"
print("Модель вызывает инструмент и переносит число верно")

Засчитано, если обе части печатают итоговую строку. Если падает последняя проверка, модель пересказала число по-своему, например округлила до рублей. Добавьте системную подсказку: «Суммы из инструмента переноси в ответ до копейки».

Сравните модели

У OpenAI-совместимых API (DeepSeek и другие) вызов инструментов называется function calling. Устроен так же, отличается формат:

python
import os
from openai import OpenAI

alt = OpenAI(api_key=os.environ["ALT_API_KEY"], base_url=os.environ["ALT_BASE_URL"])  # адрес — в документации вендора
ALT_MODEL = "впишите-имя-модели"  # актуальное имя — в документации вендора

ALT_TOOLS = [{"type": "function", "function": {
    "name": t["name"], "description": t["description"], "parameters": t["input_schema"]}} for t in TOOLS]

def ask_alt(question, log=None):
    messages = [{"role": "user", "content": question}]
    for _ in range(5):
        msg = alt.chat.completions.create(model=ALT_MODEL, messages=messages,
                                          tools=ALT_TOOLS).choices[0].message
        if not msg.tool_calls:
            return msg.content
        messages.append({"role": "assistant", "content": msg.content,
                         "tool_calls": [tc.model_dump() for tc in msg.tool_calls]})
        for tc in msg.tool_calls:
            args = json.loads(tc.function.arguments)  # здесь аргументы приходят строкой JSON
            out = vat(**args)
            if log is not None:
                log.append({"input": args, "output": out})
            messages.append({"role": "tool", "tool_call_id": tc.id,
                             "content": json.dumps(out, ensure_ascii=False)})
    raise RuntimeError("модель не закончила за 5 шагов")

Замените ask на ask_alt во второй части практики и прогоните те же пять вопросов. Смотрите: позвала ли модель инструмент на вопрос про УПД, верно ли выбрала режим, не исказила ли число. Поддержку инструментов у конкретной модели проверьте в документации вендора. Результатов прогона у нас нет: записываете вы.
